# Challenge 2.5.3 — The Deep Clean (Quality Audit & Refactoring)

## Overview
This activity, "The Deep Clean," focuses on auditing existing unit tests against a professional quality checklist and performing the necessary refactoring to eliminate technical debt, specifically around hardcoded test data.

## Task: Quality Audit
We audited the `microservices/cart-service/src/service.test.ts` file (created in Lesson 2.1) against the following criteria:

### Quality Checklist
1.  **Are all external calls mocked?**
2.  **Are there any hardcoded user IDs that should be random?**
3.  **Does every test case have an expect assertion?**

### Audit Findings (Local AI)
**Prompt:**
> "Review this test file against the following Quality Checklist:
> 
> Are all external calls mocked?
> Are there any hardcoded user IDs that should be random?
> Does every test case have an expect assertion?
> List any violations."

**AI Report Result:**
- **Mocking**: PASS (External clients are properly mocked).
- **Assertions**: PASS (Every test case has an `expect` assertion).
- **Randomization**: **FAIL**. Multiple hardcoded user IDs (e.g., `user-1`, `user-test-ai`) were identified across all test cases.

---

## Refactoring: The Deep Clean Implementation

To resolve the identified technical debt, the following actions were taken:

### 1. Setup Randomized Data Library
- **Action**: Installed `@faker-js/faker` (v7.6.0) in the `cart-service` package.
- **Note**: Version 7.6.0 was chosen to maintain CommonJS/Jest compatibility without complex ESM wrappers.

### 2. Code Refactoring [service.test.ts]
- **Old Pattern**: `const userId = 'user-1';`
- **New Pattern**: `const userId = faker.datatype.uuid();`
- **Impact**: Every test run now operates on a unique, randomized data set, preventing state collision and ensuring test isolation.

### 3. Verification
- **Test Execution**: Ran `npm test src/service.test.ts`
- **Results**: **11/11 Tests Passed**.
- **Stability**: Confirmed that the logic handles unique UUIDs correctly across additive, subtractive, and edge-case scenarios.

---

## Conclusion
"The Deep Clean" successfully transitioned the Cart Service unit tests from static, predictable data to a more robust, randomized testing model. This ensures the service's resilience against hardcoded assumptions and aligns with Senior QA best practices.
